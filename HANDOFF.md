# Budget Tracker: handoff for a new session

Read this first. It describes how the app is built, where everything lives, the owner's preferences, and how to work safely.

## What it is
A household budget PWA for **Arhaanbeta** (aarhaan22@gmail.com). One file app: `index.html` (+ `sw.js`, `manifest.webmanifest`, `icons/`), hosted on **GitHub Pages**: https://arhaanbeta.github.io/budget-tracker/. Data lives in a private Google Sheet, **"Budget Tracker data"** (owner aarhaan22@gmail.com), reached through a **Google Apps Script web app** (`apps-script/Code.gs`).

## App structure (index.html)
- **Sync:** optimistic outbox (`queue` → `flush`), full data returned by the script each time; 30 s polling; offline-safe. Ops: config, txn, deltxn, bal, delbal, fix, replace, adduser, deluser, vput, vdel, signout.
- **Overview:** KPI strip (Income, Spent, Saved, Savings rate), then one tile per category in Setup order (Cash in hand tile first if set). No group labels or commentary (owner's explicit wish).
- **Categories:** owner's canonical names; `misc` = "Miscellaneous", `disc` = "Discretionary" (`unplanned: true` → its budget equals what was spent), `schtr` = "School transport". Quick-pick buttons: `config.chips` = [groc, misc, schtr, car] pinned first; short labels `short` (groc → "Household", misc → "Misc"). Do NOT reintroduce Fixed/Variable/Sinking/Discretionary group labels anywhere visible.
- **Entry form:** Amount (calculator: + − × ÷, brackets, dictation words; `parseAmount` is a safe parser, never eval) with + − × ÷ = buttons → Category buttons (+ dictation box) → **Paid with: Cash (default) / Bank / Card** → Date: Today / Yesterday / 📅 → Note → collapsed "More" (for whom, tag, refund). The five text boxes are `contenteditable` divs (`makeTextBox`) so Chrome/SwiftKey autofill bars don't appear; they expose `.value`.
- **Payment data:** cash → `acct='cash'`; bank → `acct=<account id>`; card → `card=<card id>`; card bill payment → both (card being paid + bank). Old entries without payment stay unset unless edited.
- **Vault (Owner only, open mode):** no passphrase; rows AES-GCM with a built-in key (`vOpenKey`, SHA-256 of `budget-tracker/open-vault/v1`), meta `{v:2, mode:'open'}`. Local copy in localStorage for instant open; changes queue and sync in the background. Tables: Credit cards (CC, Name, CC number, Exp, CVV, Stmt, PW, Cust ID, Note), Savings accounts (Account, Name, Acc, Cust ID, PW, IFSC, Card no, Exp, CVV, Notes), Personal (Portal/item, ID/number, Password/note). Filters: All, Credit cards, Savings accounts, Personal, Aadhaar, Voter. Paste many rows (heading-matched), Delete all (type DELETE), per-cell copy.
- **Vault → payment lists:** `syncPayMethods()` copies **names only** (+ last 4 digits when names clash) and statement days into Setup data: `config.cards` (vault card ids, `src:'vault'`, `dueDay` kept by id, else due ≈ statement + 20 days) and `config.payBanks` (account ids in order: HDFC ARHAAN, AMMI HDFC, HDFC EFRAH, then the rest). Vault-only banks become `config.accounts` entries with `pay:true` (hidden from Wealth/Setup editor). Family phones get the buttons without vault access.
- **Wealth:** net worth = assets − debts − card bills − **this month's budget still to spend** (`budgetLeft`). Order: tiles, Assets, Debts, Still to spend, Not counted, then chart, Record today's balances, snapshots. **FD growth** view: FD accounts at latest balance, monthly compounding at 7% (editable, stored in prefs).
- **Setup:** cycle day (25), Cash in hand (`config.cashStart`), categories/budgets, accounts (net worth), account & sync, family access, backup. No card section (cards come from the vault).
- **Breakdowns ("how it is worked out"):** every figure on Overview (KPIs, category tiles, Cash in hand, card-bill rows), Wealth (KPIs, section headings, each account, Credit cards, Still to spend, snapshots, FD cards) and Card bills (KPIs, each card header) has `data-act="why" data-k="…"` (via `whyAttr`). Tapping opens `#whyScrim`; `whyBuild(k)` builds sections of signed lines that add up to each total, from the same functions the screens use (`wealthCalc`, `cardLedger`, `cashInHand`, `budgetLeft`). Lines can drill down (`why-go`, with Back) or open an entry for editing. The sheet refreshes after each sync.
- **Keyboard rules (house rule, owner insists):** (1) no Android/Google autofill bar on any box except the sign-in email (`#mEmail`, marked `data-keep-ac`; the owner wants suggestions there). `noAutofill()` turns every `<input>` (except checkbox/radio/date/file/hidden) and every editable `<textarea>` into a contenteditable `.tbox.tin` (`toTextBox`); it runs automatically on every `innerHTML` write (Element.prototype.innerHTML is wrapped) plus a MutationObserver, so new boxes are covered without extra work. The boxes keep `.value`, `.type`, `.placeholder`, `.select()`, fire `input`, and fire `change` on leaving or Enter; Enter submits the form if it has a submit button. Select them by class/id, never by the `input` tag. (2) Never redraw a screen while someone types in it: `render()`, `setView()`, resize and the sign-in screen use `holdIfTyping()`; the skipped redraw runs when focus leaves the box.
- **Address above the keyboard:** that strip is Chrome's own address bar (owner has it at the bottom), not SwiftKey or the app; a web page cannot hide it. The fix is to run the installed app (manifest `display: standalone`): Setup shows a "Use it as an app" card with an Install button (`beforeinstallprompt`) or Chrome menu steps; hidden when already installed.
- **Fixed bugs worth remembering:** never redraw screens with text boxes on `resize` (Android keyboard flapping); auto-focus only if focus isn't already in the form; vault screen redraws only when its state changes.

## Design system (owner-approved rules)
- **Colours are roles** in `:root`, stepped separately for day and night (validated with the dataviz skill's colour-blind checker). Status: `--good` green = on track, `--warn` amber = running ahead of the month, `--bad` red = over budget, `--pur` purple = spent outside the plan (unplanned categories like Discretionary, no budget, Unlisted). Each has `-soft` (backgrounds) and `-ink` (text) steps; a status colour always sits beside a word. Accent is petrol blue (kept away from purple). Don't reuse status colours for anything else.
- **Status logic** lives in `catStatus()` (one category) and `cycleOutlook()` (whole month: projected spend at the current daily rate; Fixed/Sinking-group bills count as paid in one go, never "running fast"). Overview tiles show a thin "even pace" marker.
- **Day/night**: `#themeBtn` flips `html[data-theme]`, remembered in localStorage (`budgetTracker.theme`); an inline script in `<head>` applies it before paint. Everything uses CSS variables, so charts switch without redrawing.
- **Type**: Inter for all reading and numbers (Archivo only for the name), body 17px; nothing below 13px. Big figures carry class `fit` and `fitNums()` shrinks them just enough to fit.
- **Text size and font** (`Aa` button, `textSheet()`): six fonts (Inter default, Atkinson Hyperlegible, Noto Sans, Roboto, Lexend, phone's font) and five sizes (0.9–1.35). Every font size in CSS and inline styles is `calc(Npx*var(--fs,1))`, so one variable scales the app; never write a bare px font size. Saved in localStorage `budgetTracker.text`, applied in `<head>` before paint; `bigtext` class (size ≥ 1.1) drops capitals on labels so long words fit. Chart label widths multiply by `fsNow()`.
- **Overview card summary** (`cardStripHtml`): three figures (To pay now with urgency tone, Next bills, Total owed), an owed split bar, "Pay now" rows with calendar date tiles (red overdue, amber due within 5 days), "Coming up" rows, and a count of cards with nothing due. Every row opens that card's breakdown.
- **Notes tab** (4th tab, after Wealth; owner wanted it within reach on a 6.5" phone). A small floating "+ Note" button (bottom right) opens a **plain-text** note with the cursor in the text (no choices to make); Markdown/HTML/JSON are in the "Plain text ▾" pop-up at the bottom left of the editor; choosing one shows the note formatted at once (Markdown/HTML preview, JSON checked and tidied), with Edit/Preview for those kinds. Bottom bar (owner-specified, keep exactly): kind pop-up, then Copy, Delete (two taps, "Sure?") and ✓ Save (saves and returns to the list), side by side on one line; no ⋯, no Tidy button. Notes tab: no banner text; label chips (All, Arhaan, Efrah, Others, no counts) and Search share one row. Viewport uses interactive-widget=resizes-content so the bar sits above the keyboard. Labels: **Arhaan, Efrah, Others** (owner said "Arhan/Ifra"; we used the spellings already in the app; default from the signed-in email or last used). Pinned notes sit in a "Pinned" section; newest pin goes on top; order changes by drag grip (≡) or the press-and-hold menu (Pin/Unpin, Move up/down, Label, Delete with two taps). Untitled notes are named by their first line (list and Drive file name). Plain-text notes have a toolbar: **B** bolds the selection (stored as `**word**`, shown bold; `textToRich`/`richToText`), **A− / A+** set the note text size (pref `noteSize`, CSS `--nfs`). Toolbar buttons keep the selection and keyboard (pointerdown preventDefault).
  - Storage: each note is a real file (`.txt/.md/.html/.json`) in the owner's Drive folder "Budget Tracker notes"; the sheet's Notes tab is the list (id, title, type, owner, file id, updated, size, preview, Label, Pinned, Pin order). Ops: `nput` (content + meta), `nmeta` (label/pin/order only, file untouched), `ndel`. Reply: `notes` (own notes only), `notesV: 2`, `noteBodies` for `noteIds`. App store `N` (localStorage `budgetTracker.notes.v1`: local, meta, del, bodies); `notesReply()` re-sends until the sheet matches; with an older script (notesV < 2) labels/pins stay on the phone and upload after the script update.
  - Tests: run Code.gs in a vm with fake Sheets/Drive (see "Testing approach"); a script test and an app test both pass.
- **Numbers**: always full Indian style in whole rupees (`rs()`, `INR`), e.g. ₹68,00,000. Never lakh/crore shorthand, never decimals (months of cover is rounded). `rsShort` is now just `rs`. Input boxes show amounts with Indian commas; parsers accept them.
- **Trend** (`renderTrend`): range 6/12/All (pref `trendN`); hero (saved, average spend, months within budget, best month); Income and spending columns (spent coloured by status, budget tick); selected month readout; the month day by day (spent vs budget, dashed "at this pace" projection, last month in grey); savings building up; net worth; categories × months heatmap. Tapping a month sets the app's month (`state.cur`); every figure opens a breakdown (`m:KEY`, `ov-cat:ID@KEY`, `t-saved`, `t-avg`, `t-within`).

## Owner's preferences

- Test thoroughly before pushing; never push half-done work.

## Testing approach (rebuild in the new session)
Previous tests lived in the session scratchpad and are gone. Method that worked: a Node mock server that loads `apps-script/Code.gs` in a `vm` context with fake `SpreadsheetApp`, `PropertiesService`, `LockService`, `ContentService`, `Utilities`, `MailApp`, `UrlFetchApp`, `HtmlService`, serving the app and routing `https://script.google.com/**` to it from Playwright (Pixel 7 profile). Chromium + Playwright are preinstalled. Read live data with the set-up key via `curl -sSL -H 'Content-Type: text/plain' --data '{"key":"…","vault":true,"ops":[]}' <API_URL>` (follow the redirect as GET; plain POST body).
