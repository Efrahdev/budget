# Budget Tracker: handoff for a new session

Read this first. It describes how the app is built, where everything lives, the owner's preferences, and how to work safely.

## What it is
A household budget PWA for **Arhaanbeta** (aarhaan22@gmail.com). One file app: `index.html` (+ `sw.js`, `manifest.webmanifest`, `icons/`), hosted on **GitHub Pages**: https://efrahdev.github.io/budget/ (repo `Efrahdev/budget`; moved from `Arhaanbeta/budget-tracker` in Nov 2026 after that GitHub account was blocked). ## App structure (index.html)
- **Sync:** optimistic outbox (`queue` → `flush`); polling every 60 s while the app is on screen, plus on return to the app and on reconnect; offline-safe. The script keeps a version (`REV` script property, bumped by any request with ops) and sends it as `rev`; a quiet sync (no ops, a full copy fetched in the last 10 min) sends `since: rev` and gets `{same: true}` back instead of the whole data set (`Sync.rev`, `Sync.full`). A full copy is still fetched at least every 10 min, so edits typed straight into the sheet show up. Older scripts ignore `since`, so the app works with either.
- **Out of date warning:** a failed sync (anything but a sign-in error) sets `state.stale`; `renderBanner` shows "Can't reach Google Sheets … last updated N ago" with Try again when the saved copy is over 5 min old (or changes are waiting). Re-checked every minute. The sync label adds "from N ago".
- **Entry link switched off with unsent entries:** `forgetSignIn` moves unsent `txn` ops to `budgetTracker.unsent.v1` (`keepUnsent`, with category and payment names) instead of dropping them. The banner says how many were not saved, with Copy and Discard; once someone is signed in on that phone again it also offers Save them (only on tap, never automatic). Ops: config, txn, deltxn, bal, delbal, fix, replace, adduser, deluser, vput, vdel, signout.
- **Overview:** (phones in a Chrome tab: a dismissible "Install the app" card), then the hero with Spent as the headline (bar against the month's budget + even-pace marker) and Income, Saved, Savings rate beside it, then one tile per category in Setup order (Cash in hand tile first if set), each with its category icon. No group labels or commentary (owner's explicit wish). Below the tiles: **Credit cards** (`cardStripHtml`: the three KPIs + split bar, then a `.wgrid` of gradient `.wc` cards in bank colours, most urgent first: overdue (red glow, pulsing pill) → due within 5 days (amber pill) → other unpaid → next bill → all clear; each shows To pay / Next bill / Owed, Pay By, last 4 and network from the Vault when unlocked, and a limit bar) and **Bank accounts** (`bankStripHtml`: the Add entry Bank buttons in `config.payBanks` order, else every non-stand-in Bank account; live balance via `X.res`, total in the header). `wcSplit` puts the bank on top and the person/card name under it; `wcThemes` turns repeats of the same bank round the colour wheel (`wcHue`) so the three HDFC accounts differ. Cards rise in staggered and get one light sweep while the view has `.enter`; amounts count up (`wcCount`, from `viewEntered` and `renderOverview`); all motion is off under reduced motion. Tapping a card opens its breakdown (`card:` / `w-acct:`). The old dated bill rows (`.ccr`) are gone.
- **Overview banner (`.ovb`, Nov 2026, replaces the blue `.kpis` hero on Overview only; Card bills keeps `.kpis`):** neutral graphite panel (tokens `--ovb-*`, stepped for day and night), faint grid texture, hairline structure. Top: "Budget · <cycle>" and a "Day N of M" pill. Headline: Spent (why `ov-exp`) "of ₹budget budget", beside it Left / Over by plus the status word. Thin meter (status colour + even-pace marker) with "N% used · Even pace N%". Bottom grid (2×2 on phones, 4 across from 760px): Income, Saved, Savings rate, Per day left (left ÷ days to go, today included). Status colour only on the meter and its word.

## Design system ("calm glass", Nov 2026 redesign; the owner asked for an Apple-class look and feel)
- **Shell:** one DOM for every screen size. `.shell` holds `#topbar` (logo, month picker `#cycBar`, sync dot `#status`, `#textBtn`, `#themeBtn`, `#addTop`) and `#navbar` (links with `data-v`; `.nv-2` = secondary screens; `#navMore`). **Phones/tablets (<1024px):** fixed glass top bar (58px + safe area) that slides away on scroll-down and back on scroll-up (`html.tb-hide`), a floating glass bottom bar with Overview, Entries, Wealth, Notes, More; the round `+` FAB above it (hidden on Notes, Discretionary, Setup, Vault); **More** (`openMore()`, `#moreScrim`) = tiles for Card bills, Trend, Discretionary, Setup, Vault (owner) + Day/Night, Text size, Install, Sync now. `Aa` lives in More on phones. **Laptop/desktop/TV (≥1024px):** `.shell` becomes a fixed glass sidebar (`.topbar/.tb-in/.tb-act` are `display:contents`, items ordered with `order`), page title `#pageTitle`, content max width `--vw` (1180px; 900px for Entries/Notes/Discretionary/Setup). **TV:** `--fsv` scales all type (1.12 at ≥1600px, 1.4 at ≥2400px) and focus rings thicken for remote D-pads. `markNav()` sets `aria-current`; the month label is `#cycLabel` with the real `<select id="cycPick">` laid invisibly over it (native picker, never clipped).
- **Motion:** screen changes use the View Transitions API (`navTo()`; content cross-fades, the bars do not), the new screen's cards rise in (`viewEntered()` → `.view.enter`, staggered, bars grow) and you start at the top; sheets slide up on a spring (`linear()` easing with a cubic-bezier fallback) over a blurred scrim (`@starting-style` + `transition-behavior: allow-discrete`, so `hidden` still opens/closes them); toasts rise in; buttons/chips scale on press. Everything collapses under `prefers-reduced-motion`. Android gets a 6ms tick on selection controls and 12–18ms on save/delete (`buzz()`).
- **Colours are roles** in `:root`, stepped separately for day and night, every text pairing checked to WCAG AA (≥4.5:1). ## Reader (Nov 2026): `reader/`, its own page, shown in the Reader tab
- **Why a separate page.** pdf.js is ~610 KB gzipped (4× the whole budget app); loading it at start-up doubled the budget's open time (3.1 s → 6.1 s, mid-range phone on slow 4G). So the Reader is its own page in `reader/`, and the budget app only creates an `<iframe src="reader/">` in `#v-read` the first time Reader is opened (`rdFrame()`). Budget start-up is unchanged (measured 3,118 ms → 3,162 ms; +2.2 KB gzipped). The separate page also isolates CSS, globals, listeners and memory, and carries a strict CSP (`script-src 'self' 'wasm-unsafe-eval'`, no inline scripts, no eval) that `index.html` can't have.
- **Where it sits.** Desktop sidebar link (`nv-2`); on phones the first tile in More; manifest shortcut `./#read`; a note's ⋯ menu has "Read in Reader". In the Read view the budget top bar hides (phones), and the Reader asks the budget to slide its bottom bar away while you read or while one of its sheets is open.
- **The bridge** (budget side: `RD`, `rdFrame`, `rdPost`, `rdHandle`, `rdSaveNote`, `rdDrain` before `start()`; Reader side: `reader/js/bridge.js`). postMessage, same origin only. Reader → budget: `hello`, `save-note`, `bars`, `immersive`, `open-note`. Budget → Reader: `hello` (labels, default label, signed in), `note-saved`, `shown`, `hidden`, `inset` (px the bottom bar takes), `open-text`. "Save to Notes" calls the budget's own `noteSave()`, so notes sync to Drive exactly like typed ones (max 400,000 characters). A Reader opened on its own asks over `BroadcastChannel('budget-reader')`; if no budget tab answers, the note waits in `localStorage['budgetTracker.readerInbox.v1']` and `rdDrain()` adds it on the next start.
- **Storage.** Documents, reading positions and Liquid caches live in IndexedDB (`budget-reader`: `docs` + `bodies`, max 40 items), never in localStorage (its ~5 MB is shared with the budget's cache, outbox and notes, and `saveNotes()`/`saveCache()` swallow quota errors). Prefs: `budgetReader.prefs.v1` (tiny).
- **Service worker** (`sw.js`, v68). FRESH FIRST: pages (`freshPage`, fetched by URL because a navigation request can't be cloned with options) and all same-origin app files (`fresh`) are fetched with `{cache:'no-cache'}` when online, so a deploy shows on the next open. (Until v67 app files were stale-while-revalidate and also obeyed GitHub's `max-age=600`, so phones kept showing the previous version after an update.) Saved copies are only the offline fallback. Pages are cached under their own URL (`pageKey()`); before, every navigation was stored as `index.html`, which would have let the Reader overwrite the saved budget app. `reader/vendor/**` (pinned pdf.js 6.5.438, marked 18.1.3) is cache-first in `reader-vendor-v1`, kept across budget updates. Nothing of the Reader is in `SHELL`.
- **Modules** (`reader/js/`): `app.js` (library, open, paste, reading surface, modes, panels, export), `flow.js` (reflow column, chunking with `content-visibility`, the reading anchor = block + character, table → cards), `zoom.js` (pinch, trackpad, Ctrl ±/0 → font size), `sanitize.js` (allowlist cleaner; style → `<strong>/<em>/<u>/<s>`; Word lists; drops all styles, scripts, handlers, `javascript:`), `formats.js` (sniff, decode, marked, plain text, paste detection), `pdfdoc.js` (lazy pdf.js, Original layout with pdf.js viewer components), `liquid.js` (Liquid mode: tagged-PDF struct tree when it covers ≥60% of a page's text, otherwise layout analysis: columns, lines, paragraphs, headings by size, lists, running headers/footers, de-hyphenation; scanned pages kept as images), `exporter.js` (Markdown tuned to the Notes renderer, text, note HTML, styled standalone HTML, Save As / share / download), `search.js` (CSS Custom Highlight API), `store.js`, `prefs.js`, `util.js`.
- **Known limits.** iPhone Safari has no element fullscreen, so the Full screen button becomes immersive mode there. Liquid mode is weak on tables and forms (use Original). Pasted web content may load remote images. Bump `LIQ_VER` in `app.js` when `liquid.js` output changes.
- Tests (scratchpad, gone with the session): `t1` phone formats, security, no-spill at 100–320%, all PDF modes; `t2` desktop paste, notes, every save format, search, contents, pinch, resume; `t3` inside the budget app (phone + desktop: zero Reader requests until opened, bars, save to Notes, View, Read in Reader, mailbox); `t4` service worker over local HTTPS + offline; `t5` 157k-word book, touch pinch anchor, paste fallback, theme following.
